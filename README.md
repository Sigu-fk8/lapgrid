# LAPGRID — Circuit Performance

サーキットのラップタイムと、車両・タイヤ・気象・路面・タイヤウォーマー条件を記録／比較する試作品。

## 今回の構成

- `index.html`: 単体で動く操作可能なUI試作品。HTML/CSS/JavaScriptのみで、ローカルブラウザに記録を保存します。
- `supabase/migrations/001_initial_schema.sql`: Supabase/PostgreSQL向けの初期データモデルとRLSポリシー。
- `supabase/migrations/002_harden_moderation.sql`: 通常ユーザーが自分の投稿を承認済みにできないようにする追加SQL。
- `SETUP_GUIDE_JA.md`: クラウド化と公開に向けた日本語セットアップガイド。
- `.env.example`: 次段階のSupabase接続で使う環境変数名。

## 試作品を起動する

`index.html` を最新のブラウザで開きます。投稿したデータとマイガレージは、そのブラウザの `localStorage` に保存されます。別端末や別ブラウザとの同期はありません。ランキングの初期データは架空のサンプルで、実在の公式リザルトではありません。

## クラウド版へ進む手順

1. Supabaseで新しいプロジェクトを作る。
2. SQL Editorで `supabase/migrations/001_initial_schema.sql` を実行する。
3. 続けて `supabase/migrations/002_harden_moderation.sql` を実行する。
4. Authenticationでメール認証方式とリダイレクトURLを設定する。
5. Next.jsアプリを作成し、Supabaseの公式クライアントをサーバー／ブラウザの責務に応じて設定する。
6. `.env.example` の値をローカル `.env.local` とホスティング先の環境変数に設定する。`service_role` キーはクライアントに絶対に公開しない。
7. ログイン、車両登録、走行記録CRUD、ランキングAPIを順番に接続する。
8. テスト用アカウント2つでRLSを検証し、他人の非公開記録を読めない・編集できないことを確認する。
9. 気象APIはサーキット位置と走行時刻で取得し、取得元・観測時刻・気圧の種類を保存する。実測値と推定値は別フィールド／ラベルで扱う。
10. 公開前に規約、通報・モデレーション、プライバシー、ログ保持、バックアップを整える。

## 重要なデータ設計

- ラップタイムは表示文字列ではなく整数ミリ秒 (`lap_time_ms`) で保存し、数値で順位付けする。
- コース名とコースレイアウトを分ける。別コースのタイムを同一ランキングに混在させない。
- 証跡は `self_reported` / `gps_log` / `official_result` として区別する。証跡があることと、運営確認済みであることは別扱い。
- 気圧は現地気圧・海面更正気圧を区別する。気温・気圧はデータの取得元と観測時刻を保存する。
- ウォーマー設定温度、加熱時間、取り外し時タイヤ温度は別々に記録する。設定値を実測値と混同しない。
- 初期スキーマでは投稿は `pending` とし、管理者の承認後に公開ランキングへ反映する設計。管理者の審査画面・権限は別途実装が必要。
